# Security

- Perform Kimi, DeepSeek and GLM login yourself. Never send passwords, OAuth tokens, cookies or browser profile files to another person.
- Keep both services on loopback: gateway `127.0.0.1:8790`, browser bridge `127.0.0.1:8788`.
- Use long independent local API keys generated by the setup script.
- API provider secrets are read from `.env`, copied only into the child Kimi Code process environment, and never returned by diagnostics.
- Limit `DEFAULT_WORKSPACE` and `ALLOW_PATHS` to trusted project roots.
- The main orchestrator is the single writer by default; external model workers are read-only reviewers.
- `execute` requires approval. `yolo` is disabled and must run in a project-scoped container/VM if enabled.
- Browser fallback is advisory-only. It must not automate CAPTCHA, rotate accounts, evade quotas or expose a public proxy.
- Treat `.env`, `data/`, `audit.jsonl`, browser profiles and Kimi Code home as secrets.
- Review MCP servers before enabling them; an MCP tool can have privileges beyond this gateway's file callbacks.
- Inspect generated diffs and test evidence before merging or deploying.
